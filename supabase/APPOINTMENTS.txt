CAN WASH - SISTEMA DE CITAS EN LA BASE LOCAL
Fecha: 2026-11-17

ESTADO
Las migraciones 20261117000002 a 20261117000009 se aplicaron SOLO a la base local.
No se modifico la base de la nube. Los componentes React ya incorporan formularios
de mascotas y domicilios, cotizacion, disponibilidad y reservas por visita.
Mis citas agrupa mascotas, pagos e historial y permite cancelar y reprogramar.
El personal dispone de agenda, valoraciones, recorridos y pagos. Administracion
permite gestionar tarifas, descuentos, horarios, cierres, origen y cuentas.
.env.local conecta src/lib/supabase.js a http://127.0.0.1:54321.
Reiniciar Vite con npm.cmd run dev si estaba abierto antes del cambio de entorno.
Studio: http://127.0.0.1:54323.

MODELO
- visitas: agrupa todas las mascotas, un traslado, descuento, total y cotizacion.
- agenda_estilistas: intervalos de visitas y bloqueos manuales; restriccion GiST
  que impide cruces para el mismo estilista incluso ante solicitudes simultaneas.
- citas y detalle_cita se conservan como atencion y servicios de cada mascota.
- pagos admite una cita antigua O una visita nueva, nunca ambos destinos.
- eventos_visita: historial de reservas, cambios, valoraciones y pagos.
- configuracion_negocio, horarios_laborales y cierres_negocio: reglas de agenda.
- estilistas: se creo un cupo "Estilista principal"; admite solo uno activo.
- direcciones_cliente: domicilio y recorrido validado desde el origen.
- razas: lista inicial ampliable de perros y gatos, con Mestizo y Otra.
- mascotas agrega longitud, capa, estado del pelo y datos de valoracion profesional.
- servicios/precios_servicio agrega paquetes, extras y componente de bano.

REGLAS APLICADAS
Horario America/Merida: 08:00 a 16:00, domingo a sabado excepto miercoles.
La atencion completa debe terminar antes de las 16:00. Se reserva una hora
adicional despues de cada visita; esa hora puede quedar despues del cierre.
Inicios cada 15 minutos. La duracion real calculada se redondea hacia arriba
al minuto, no a bloques de 15.
Duracion = ceil((banos + adicionales + visita ANTES DEL DESCUENTO) * 60 / 100).
Traslado = max(40, round(kilometros * 10, 2)). Los kilometros admiten 3 decimales.
Descuento = round((componente de bano + visita) * porcentaje / 100, 2).
2 mascotas: 5%; 3: 10%; 4 o mas: 15%. No se descuentan adicionales.
La administracion puede ajustar porcentajes hasta 15%; una mascota mantiene 0%.
El paquete con rapado se divide en bano base + $100. Desenredado: bano + $200.
No se suma dos veces el bano. El corte de garras individual no se agrega a banos.
Asuntol $50, garras individuales $35, doble capa $100, manejo dificil $100,
caso extremo $400. Gato: bano $150, con rapado $250, con desenredado $350.
El gato se normaliza al tamano CHICO pero tiene sus propias tarifas.
Doble capa, manejo dificil y caso extremo se agregan automaticamente cuando
el perfil declarado los requiere. Desenredado y caso extremo bloquean tiempo
como PENDIENTE_VALORACION hasta aceptarse la valoracion.
Caso extremo y desenredado no se acumulan. Pelaje ENREDADO requiere seleccionar
rapado o desenredado; no se cotiza como bano normal.
La cantidad total de mascotas de la visita determina el porcentaje, que solo
se aplica a la base descontable (bano y visita).

PESOS PROVISIONALES, SIN LIMITES COMPARTIDOS
0 < peso < 5: CHICO; 5 <= peso < 15: MEDIANO;
15 <= peso < 30: GRANDE; peso >= 30: GIGANTE.
Los perros necesitan peso positivo para cotizar. El tamano se calcula en servidor.
Estos umbrales son provisionales; ajustarlos mediante otra migracion cuando
el negocio confirme los limites exactos.

ORIGEN Y KILOMETRAJE
El enlace compartido resuelve al pin de Heroico Colegio Militar 1, Barrio de Santa
Ana, Campeche: latitud 19.8399021, longitud -90.5336569. Se uso el punto de lugar
!3d/!4d y no el centro de camara @19.8399021,-90.5358221.
No se invento una coordenada diferente para un mercado.
La base no consulta Google Maps ni un calculador de rutas por si sola.
Por ahora el personal valida la distancia por calles con validar_distancia_direccion.
Esto permite probar y operar con validacion manual antes de integrar un proveedor
de rutas en el backend. Nunca aceptar el costo o kilometraje que proponga un cliente
sin validarlo. Editar el domicilio o el origen invalida la distancia previa.
El recorrido tarifado se mide del origen al domicilio indicado; no se duplica
automaticamente para ida/vuelta ni se optimiza la ruta entre visitas.

PUESTA EN MARCHA DE CUENTAS
No se crearon usuarios reales. Para una demostracion sintetica opcional, ejecutar
npm.cmd run db:demo en local y consultar backups/demo-access.json (fuera de Git).
No reemplaza una cuenta ya asociada al estilista ni acepta una URL remota.
Para las cuentas definitivas:
Registrar una cuenta local y asignarle ADMIN manualmente en Studio para administracion.
Registrar la cuenta EMPLEADO del estilista. Desde una sesion de administrador:
  rpc('asignar_cuenta_estilista', { p_id_usuario: 'UUID_DE_LA_CUENTA_EMPLEADO' })
Antes de asignarlo existe un cupo de agenda, pero el panel del empleado no podra
ver las citas asociadas a ese cupo hasta enlazar su cuenta.

CONTRATO UTILIZADO POR LOS FORMULARIOS
1. Crear/editar el perfil del cliente y registrar mascotas con peso y pelaje.
2. INSERT direcciones_cliente: id_cliente, direccion, colonia, latitud, longitud.
3. Personal: rpc('validar_distancia_direccion', {p_id_direccion: 1, p_kilometros: 7.5}).
4. rpc('cotizar_visita', {p_id_direccion: 1, p_mascotas: [
     {id_mascota: 1, paquete: 'BANO_INTEGRAL', extras: ['ASUNTOL']},
     {id_mascota: 2, paquete: 'BANO_RAPADO', extras: []}
   ]}). Las mascotas deben pertenecer al cliente del domicilio.
5. rpc('horarios_disponibles', {p_fecha: 'AAAA-MM-DD', p_id_direccion: 1,
     p_mascotas: [...]}) devuelve inicios y finales con zona horaria, importe y duracion.
6. rpc('reservar_visita', {p_inicio: 'AAAA-MM-DDT08:00:00-06:00', p_id_direccion: 1,
     p_mascotas: [...], p_total_esperado: COTIZACION.total,
     p_duracion_esperada: COTIZACION.duracion_minutos, p_solicitud: crypto.randomUUID()}).
   Devuelve id_visita. Conservar p_solicitud al reintentar la misma solicitud:
   la misma solicitud no crea dos reservas. Regenerarlo para una reserva diferente.
   Se recalculan importes en servidor y se valida nuevamente la agenda al guardar.
7. Leer visitas y relacionar agenda_estilistas/citas para mostrar resumen e historial.

OTRAS OPERACIONES
cancelar_visita(p_id_visita), reprogramar_visita(p_id_visita,p_inicio).
horarios_reprogramacion(p_id_visita,p_fecha) consulta huecos conservando duracion
y margen de la reserva original; excluye su propio intervalo. No usa una nueva
cotizacion que pudiera incorporar tarifas cambiadas despues de reservar.
bloquear_agenda(p_inicio,p_fin,p_motivo), liberar_bloqueo(p_id_agenda).
cambiar_estado_visita(p_id_visita,p_estado): pendiente -> confirmada -> en proceso
-> completada. Una pendiente de valoracion requiere valorar_visita primero.
actualizar_mascota_valorada(p_id_visita,p_id_mascota,p_peso,p_longitud_pelo,
p_tipo_capa,p_estado_pelaje,p_manejo_dificil): solo personal asignado/administrador.
valorar_visita(p_id_visita,p_mascotas,p_total_aceptado): guarda la aceptacion del
importe, revisa cierre y evita invadir la siguiente reserva. Si no cabe, reprogramar.
La valoracion mantiene las mismas mascotas. Para cambiar mascotas, cancelar y reservar.
Si el nuevo total es menor que lo ya pagado, registrar primero el reembolso.
registrar_pago_visita(p_id_visita,p_monto,p_tipo,p_metodo,p_referencia,p_estado).
validar_pago_visita(p_id_pago,p_aprobar). Estos registran movimientos; no realizan
transferencias, cobros bancarios ni reembolsos externos.

SEGURIDAD Y COMPATIBILIDAD
Se activo RLS en todas las tablas publicas. Clientes solo leen su informacion;
el personal ve las visitas asignadas y los administradores gestionan el negocio.
Las distancias pendientes son visibles para el personal que debe validarlas.
No hay escrituras directas desde el cliente a agenda, visitas, detalles o pagos.
Las funciones internas viven en privado y no estan expuestas como RPC.
El registro sin metadato rol ahora crea CLIENTE. ADMIN sigue asignandose manualmente.
Las reservas guardan precios, tiempo, mascota y domicilio como snapshots; cambiar
el catalogo o un perfil no modifica reservas anteriores automaticamente.
Antes de llevarlo a la nube, conciliar citas antiguas sin duracion: bloquean la
oferta automatica de su dia para evitar solapamientos por estimaciones inventadas.
Los paneles React muestran el total de visita, descuento y pagos agrupados.
Las citas antiguas sin id_visita se conservan para consulta y conciliacion.
No se distribuye el traslado ni el descuento entre mascotas artificialmente.
